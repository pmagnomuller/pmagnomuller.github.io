Clean code is code that is easy to read, easy to change, and clearly intentional. Bad code compounds: teams slow down, fear changes, and spend more time decoding than delivering.

## Cost of a mess

Mess does not save time. It burns productivity immediately and makes “later cleanup” unrealistic. Big-bang rewrites usually copy the same habits into a new codebase. The way to go fast is to keep the code clean as you go.

## What “clean” sounds like

Different practitioners emphasize different facets; together they form a useful checklist:

- Elegant, focused, does one thing well (Stroustrup)
- Simple and direct; reads like prose; crisp abstractions (Booch)
- Readable and enhanceable by others; tested; minimal explicit dependencies (Thomas)
- Looks like someone cared (Feathers)
- Beck’s simple-design rules: tests, no duplication, expresses intent, minimizes entities (Jeffries)
- Each routine is pretty much what you expected (Cunningham)

## Practice

The Boy Scout Rule: leave the campground cleaner than you found it. Small, continuous cleanups beat redesigns in the sky.

Professionalism is not speed-at-all-costs. Wading through mess is slower than writing clean code in the first place.
